# 04 模型家族与训练生命周期

对应 PDF：第 3 章（物理页 32-57）、第 4 章（物理页 58-73）。本章不要求下载 BERT、T5 或 GPT 权重；目标是能从“可见信息、输出形式、训练目标”推导它们的差别。

## 本章要回答的问题

1. Encoder-only、Encoder-Decoder、Decoder-only 为什么不是简单的模型大小区别？
2. MLM、Seq2Seq、CLM 分别让模型预测什么？
3. Pretrain、SFT、偏好对齐各改变了哪一层问题？
4. 为什么本项目先训练 TinyGPT，而不是复刻完整 RLHF？

## 1. 从 mask 推导三类架构

### Encoder-only

一个位置可以读取左右两侧上下文，因此得到的是双向表示。BERT 的典型预训练任务 MLM 会遮掉部分 token，再根据两侧上下文恢复它。

```text
输入：  今 天 [MASK] 很 好
可见：  左右两侧都可见
输出：  被遮位置的 token 分布
```

它擅长分类、匹配、实体抽取等“理解型”任务。它不是不能生成任何文字，而是架构和训练目标没有天然形成逐 token 自回归生成接口。

### Encoder-Decoder

Encoder 双向读取源序列；Decoder 用因果 mask 读取已经生成的目标，并通过 cross-attention 读取 Encoder 表示。

```text
源文本 -> Encoder states ──────┐
目标前缀 -> causal Decoder <───┘ -> 下一个目标 token
```

它很适合翻译、摘要等“输入序列到输出序列”的条件生成。T5 进一步把多种任务统一为 text-to-text。

### Decoder-only

整个序列都用因果 mask。GPT、LLaMA 以及本项目 TinyGPT 都属于这一类。

```text
x1 -> 预测 x2
x1 x2 -> 预测 x3
x1 x2 x3 -> 预测 x4
```

统一的 next-token 接口使自然语言任务很容易表示为“给定提示，继续生成”。

## 2. 三种目标函数

### MLM：Masked Language Modeling

只在被遮位置计算 loss。它使用双向上下文，但预训练时存在人为的 `[MASK]` 形式。

### Seq2Seq

给定源序列，让 Decoder 预测目标序列。训练时目标输入通常右移一位；不能把完整目标原样同时作为可见输入和答案。

### CLM：Causal Language Modeling

\[
\mathcal L_{CLM}=-\sum_{t=1}^{T}\log P(x_t\mid x_{<t})
\]

实现时从同一 token 窗口构造：

```python
window = token_ids[start : start + T + 1]
x = window[:-1]
y = window[1:]
```

预测问题：若忘记右移，模型可能学到什么投机路径？答案：如果当前位置能直接看到同一标签，就不再是 next-token 学习。

## 3. LLM 的训练生命周期

PDF 物理页 62 用 Pretrain -> SFT -> RLHF 展示常见流程。更准确地说，这是目标逐步改变，而不是简单“继续多训练几次”。

| 阶段 | 数据 | 目标 | 得到的能力/倾向 |
|---|---|---|---|
| Pretrain | 大量通用文本 | 下一个 token | 语言模式、通用表示和知识统计 |
| SFT | 指令-回答、多轮对话 | 在回答位置做 CLM | 按任务格式回答、遵循指令 |
| Preference alignment | chosen/rejected 或奖励 | 偏好目标、KL 约束等 | 更倾向人类偏好的行为 |

### SFT 的关键不是加一句“请回答”

假设输入是：

```text
用户：为什么需要因果掩码？
助手：它阻止当前位置读取未来 token。
```

常见做法是把用户和格式 token 的 label 设为 `-100`，只在助手回答位置计算交叉熵。这样模型接收完整提示，但监督信号集中在要学的回答上。

### 偏好对齐的最小直觉

同一个 prompt 有回答 A 和 B，人类标注 `A > B`。训练目标让 chosen 的相对分数更高。完整 PPO 会涉及 Actor、Reference、Reward、Critic，工程门槛远超原理入门；DPO 等方法用成对偏好数据构造更直接的目标。

本项目在必做路线中只要求理解数据对、相对偏好和“不要偏离参考模型过多”的原因，不在普通 CPU 上复刻生产 RLHF。

## 4. 一个 loss mask 纸笔实验

为下面序列标出是否计算 loss：

```text
<user> 1+1 等于几？ <assistant> 2 <eos>
```

推荐答案：

```text
token: <user> 1 + 1 ... <assistant> 2 <eos>
label:  -100 -100 ...     -100    2 <eos>
```

再思考：多轮对话时，是只监督最后一轮 assistant，还是监督每一轮 assistant？两者都可以，但必须明确数据和目标，不能硬编码某个 Tokenizer 的 token id。

## 5. 常见误区

- “参数超过某个固定数就自动出现智能”：能力随数据、训练、评测和规模共同变化，所谓涌现也受指标离散化影响。
- “SFT 把所有事实写进模型”：SFT 主要学习任务格式与行为，也会改变知识，但不是可靠数据库写入。
- “RLHF 让回答必然正确”：它优化偏好，可能改善有用性与安全性，但不等于事实证明。
- “Decoder-only 只能看左边，所以完全不理解整句”：在预测较后 token 时，它已经读取了此前整段；限制的是单次位置的信息方向。
- `C≈6ND` 或某个 token/参数比例是永久定律：它们是特定假设下的经验近似，不是跨时代常数。

## 6. 出门测

1. 解释题：为什么 BERT 的双向注意力不能直接用于标准左到右生成？
2. 计算题：长度 6 的 CLM 序列能形成多少个 next-token 监督位置？
3. 调试题：SFT loss 几乎为 0，但输出只复制 prompt。检查输入/标签是否错位，是否把 prompt 自己作为同位置答案。
