## 本节问题

### 为什么一定要使用虚拟环境？

因为同一台电脑上的不同项目，可能需要不同版本的 Python 包。直接向系统 Python 安装依赖，会让这些项目互相影响：今天升级 NumPy 解决了 A 项目，明天 B 项目可能就无法运行。

虚拟环境 `.venv` 相当于项目自己的工具箱：

- Python 可执行文件位于当前项目的 `.venv` 中；
- `pip` 安装的包进入 `.venv`，而不是系统环境；
- 删除项目时可以连同 `.venv` 一起删除，不必清理系统 Python；
- 不需要“激活”环境也能使用它，只要始终显式调用 `\.venv\Scripts\python.exe`。

### 为什么实验要固定随机种子？

神经网络会随机初始化权重，也常会随机抽取训练样本。如果每次运行都完全不同，就很难判断结果变化究竟来自代码修改，还是来自随机性。固定种子不是消除所有误差，而是让小实验更容易复现和比较。

## 直觉：先检查实验台，再做实验

做化学实验前，会先确认器皿干净、标签正确、仪器校准。LLM 实验也一样：

- `sys.executable` 是正在使用的“仪器”；
- `sys.prefix` 是包的安装位置；
- PyTorch 和 NumPy 版本是实验条件；
- 随机种子检查是一次简单校准；
- CPU/GPU 只是计算设备。这里显示 CPU 完全正常，因为当前课程刻意把模型缩小到 CPU 可运行的规模。

## 定义

Python 运行时提供两个很有用的路径：

- `sys.base_prefix`：创建虚拟环境所用的基础 Python；
- `sys.prefix`：当前解释器的环境根目录。

在标准 `venv` 中，应满足：

```text
sys.prefix != sys.base_prefix
```

同时，当前解释器路径应落在项目内：

```text
D:\path\to\LearnLLM\.venv\Scripts\python.exe
```

这两个条件一起使用，比只看命令行前面是否出现 `(.venv)` 更可靠。

## 本节的“形状”观念

环境检查还没有进入模型，但从现在开始要养成记录形状的习惯。约定：

| 符号 | 含义 | 示例 |
| --- | --- | --- |
| `B` | batch size，一次处理多少条样本 | `2` |
| `T` | sequence length，一条样本有多少个 token | `8` |
| `D` | embedding/model dimension，每个 token 的向量长度 | `16` |
| `V` | vocabulary size，词表中 token 的数量 | `128` |
| `H` | number of heads，注意力头数 | `4` |
| `D_h` | 每个头的维度，`D / H` | `4` |

后续看到 `(B, T, D)` 时，不要把它当作三个神秘数字。它只是在说：一批序列、每条序列的若干位置、每个位置的一条向量。

## Windows：从零建立并验证 `.venv`

以下命令均在 PowerShell 中执行。先进入项目目录：

```powershell
Set-Location 'D:\path\to\LearnLLM'
```

项目已经提供初始化脚本。即使 PowerShell 不允许直接执行本地脚本，也可以只为这一次进程使用 Bypass：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
```

初始化完成后，不依赖“激活”动作，直接检查解释器：

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print('isolated =', sys.prefix != sys.base_prefix); print('prefix =', sys.prefix); print('base =', sys.base_prefix)"
```

再检查 pip 的归属位置：

```powershell
.\.venv\Scripts\python.exe -m pip --version
```

最后运行第一个实验：

```powershell
.\.venv\Scripts\python.exe .\experiments\00_environment_check.py
```

注意：以后安装包也始终使用下面的形式，而不是裸写 `pip install ...`：

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

## 运行前先预测

在按 Enter 之前，先把你的预测写下来：

1. `sys.executable` 应该包含哪个目录？
2. `isolated` 应该是 `True` 还是 `False`？
3. 如果没有 NVIDIA 显卡，实验是否应该失败？
4. 连续两次使用相同种子生成的随机张量，应该相同还是不同？

推荐答案：路径应包含 `.venv\Scripts`；`isolated` 应为 `True`；没有 GPU 不应失败；同一种子产生的检查值应一致。

具体版本号和随机数可能随依赖版本变化，但输出应具有下面这些信息：

```text

Virtual environment: True
NumPy: <版本号>
PyTorch: <版本号>
Device: cpu
Reproducible random check: True
Environment check passed.
```

以不变量为准，不要机械比对示例中的每个字符：

- [ ] Python 路径位于当前项目的 `.venv\Scripts`；
- [ ] 虚拟环境检查为真；
- [ ] NumPy 和 PyTorch 可以导入；
- [ ] 设备为 `cpu` 时仍然通过；
- [ ] 相同随机种子的结果相同；
- [ ] 进程以退出码 `0` 结束。

还可以用下面的命令确认依赖确实安装在虚拟环境中：

```powershell
.\.venv\Scripts\python.exe -c "import numpy, torch; print(numpy.__file__); print(torch.__file__)"
```

两个路径都应位于 `.venv\Lib\site-packages` 下。

## 常见故障与排查

### 1. 找不到 `.\.venv\Scripts\python.exe`

现象：PowerShell 报“无法将该项识别为 cmdlet”或路径不存在。

检查：

```powershell
Test-Path .\.venv\Scripts\python.exe
```

若为 `False`，重新执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
```

### 2. `bootstrap.ps1` 被执行策略阻止

不要修改整台电脑的永久执行策略。使用本节给出的 `powershell -ExecutionPolicy Bypass -File ...`，它只影响这次子进程。

### 3. `ModuleNotFoundError: No module named 'torch'`

通常是依赖没有装入当前 `.venv`，或者运行了系统 Python。执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__)"
```

### 4. 输出显示 `Device: cpu`

这是预期结果，不是降级错误。课程的核心实验不要求 CUDA。将来使用 GPU 时，也必须先让 CPU 小实验通过，因为小实验更快、更容易定位逻辑错误。

### 5. 中文显示为乱码

先确认终端使用 UTF-8：

```powershell
chcp 65001
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
```

再重新运行实验。源文件和数据文件应保存为 UTF-8。

### 6. 明明在 `.venv`，`pip` 却指向别处

不要使用裸命令 `pip`。始终使用：

```powershell
.\.venv\Scripts\python.exe -m pip --version
```

`python -m pip` 会把 pip 明确绑定到前面的 Python 解释器。

## 实验记录方法

每次实验至少记录五项：

```text
日期：
实验编号：
运行前预测：
实际输出：
预测与实际不同的原因：

```

最重要的习惯是“先预测，再运行；一次只改一个变量”。只看成功输出，容易形成“代码能跑就等于理解”的错觉。

3. 解释为什么“固定随机种子”不等于“所有电脑的浮点结果逐位相同”。提示：考虑硬件、线程和数值库。
