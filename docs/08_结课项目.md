# 08 结课项目：可复现的微型 LLM 实验报告

结课目标不是生成最像人类的句子，而是证明你能提出问题、实现机制、建立基线、控制变量、解释结果并诚实记录局限。

## 任选一个方向

### A. TinyGPT 训练研究

研究问题示例：上下文长度、层数或 embedding 维度如何影响参数量、训练速度和验证 loss？

最低交付：两个配置、相同语料/seed/步数、训练曲线、生成样例和过拟合分析。

### B. Attention 消融

研究问题示例：移除 `sqrt(d_k)`、移除 causal mask 或改变头数会发生什么？

最低交付：正确实现、一个错误/对照实现、shape 测试、未来泄漏测试、权重分布统计。

警告：移除 causal mask 的模型可能得到更低训练 loss，因为它偷看答案；这不是更好的语言模型。

### C. LoRA 参数效率

研究问题示例：rank 1/2/4/8 对可训练参数、收敛速度和最终误差的影响。

最低交付：base 冻结证明、参数表、loss 曲线、合并输出检查。

### D. Tiny RAG 评测

研究问题示例：chunk size、overlap 或 top-k 对 Recall 与上下文噪声的影响。

最低交付：不少于 10 篇小文档、20 个带标注查询、Recall@k、失败分类、来源示例和一次消融。

## 必须提交的目录

```text
report/
├─ README.md              # 研究问题与结论
├─ config/                # 所有配置和随机种子
├─ results.csv            # 原始指标，不只截图
├─ examples.md            # 成功与失败样例
└─ limitations.md         # 局限、风险和下一步
```

代码应能从项目根目录执行，不要硬编码本机绝对路径。

仓库提供了一份可重新运行的完整示例：[Attention 缩放消融报告](https://github.com/yuweiyang9611/LearnLLM/tree/main/examples/capstone_attention)。先运行它，核对 `results.csv` 与结论的对应关系，再选择自己的问题；不要只改标题或复制示例结论。

## 报告结构

1. 问题：可证伪、只包含主要自变量。
2. 假设：运行前预期及理由。
3. 方法：数据、切分、模型、参数、seed、硬件。
4. 基线：随机、未训练、关闭某组件等。
5. 指标：为何这个指标能回答问题。
6. 结果：原始数据和汇总，不隐藏失败 run。
7. 分析：现象是否支持假设，有哪些替代解释。
8. 失败案例：至少 3 个，按根因分类。
9. 局限：哪些结论不能外推。
10. 复现命令：新终端里从环境检查开始。

## 评分量表（100 分）

| 维度 | 分值 | 满分标准 |
|---|---:|---|
| 环境与复现 | 20 | venv、依赖、seed、命令和数据路径完整 |
| 实现正确性 | 25 | 单测覆盖关键不变量；无数据泄漏 |
| 实验设计 | 20 | 有基线，单变量，有合理指标 |
| 结果与分析 | 20 | 原始数据、趋势、失败案例、替代解释 |
| 文档与边界 | 15 | 能清晰复述，并诚实说明玩具实验局限 |

## 完成定义

- 一条命令可运行快速测试。
- 另一条命令可重现实验主要结果。
- 至少一个结论由自动检查或量化指标支持。
- 至少一个原假设被数据修正，或说明为何没有。
- 明确区分“代码管线运行成功”和“模型能力足够好”。

## 可复制的版本 2 配置消融

以下示例只改变 embedding 维度，使用相同 seed、步数、语料和其他配置。输出目录带时间标签，重复运行不会覆盖旧实验。

```powershell
$Tag = Get-Date -Format yyyyMMdd-HHmmssfff
$RunA = ".\outputs\pretrain\width32-$Tag"
$RunB = ".\outputs\pretrain\width64-$Tag"
.\.venv\Scripts\python.exe .\experiments\06_train_tiny_gpt.py `
  --quick --seed 42 --n-embd 32 --output-dir $RunA
.\.venv\Scripts\python.exe .\experiments\06_train_tiny_gpt.py `
  --quick --seed 42 --n-embd 64 --output-dir $RunB
.\.venv\Scripts\python.exe .\scripts\plot_experiments.py `
  $RunA $RunB --output-dir ".\outputs\plots\width-$Tag"
```

每个运行目录有 `pretraining.json`、`pretraining.csv` 和 `plots/`。比较图显示原始 loss 曲线、可训练参数量和耗时，`runs.json` 将图中短标签对应到完整配置与数据指纹。英文图内标签避免中文字体依赖：Training/Validation loss 表示训练/验证损失，Trainable parameters 是可训练参数量，Training duration 是包含记录开销的训练循环耗时。

默认不会因为效果不达标丢掉实验。报告必须同时检查执行 `status`、效果 `quality_status`、逐项 `checks` 与完成的 seed 数量；不要将缺失 seed 当零。跨配置保持各组独立，均值和总体标准差只在同一运行的同一分支内计算；单 seed 的标准差为零不代表估计没有不确定性。

要在其中一份 base 上做 SFT，显式传 `--base-checkpoint "$RunA\base.pt"`。SFT 结束后通过 `--run-dir`、`--branch full|random|lora` 和 `--seed` 指定具体模型。旧版产物不兼容版本 2；重新训练时保留旧文件用于核对，不混合新旧指标。
